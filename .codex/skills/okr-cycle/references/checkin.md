# ACTIVE OKRのチェックイン

週次チェックインでは目標を書き換えるのではなく、観測結果と判断を追加する。月末には別途 [monthly-review.md](monthly-review.md) に従って月次マイルストーンをレビューする。

## 入力

各KRについて次を確認する。

- 現在値と観測日
- 測定元
- 前回からの変化
- 期間内達成の見通しと、その根拠
- 阻害要因、依存関係、必要な意思決定
- 継続、変更、停止するInitiative

取得できない値は推測せず `UNVERIFIED` とする。数字だけが提供された場合は、測定元と観測日を確認するまで正式な実績値として扱わない。

## 更新

1. `key_results[].actual` を根拠付きで更新する。
2. `checkins` に日時、更新者、要約、confidence、blockers、decisionsを追記する。
3. Initiativeは追加・変更できるが、Objective、baseline、target、classificationは無断で変更しない。
4. 検証スクリプトを実行し、結果を報告する。

進捗率は、指標の方向と計算方法が明確な場合だけ計算する。0～100%へ機械的に丸めても意味を保てない指標では、現在値と説明をそのまま示す。

## 目標変更

目標変更の依頼を受けた場合は、次を先に提示する。

- 変更前と変更後
- 変更理由
- 難易度と解釈への影響
- 過去データとの比較可能性
- 変更しない場合の代替策

明確な人間承認後に変更し、`history` に `TARGET_CHANGE_APPROVED` として記録する。単なる進捗不良を理由に、達成しやすい値へ自動変更しない。
